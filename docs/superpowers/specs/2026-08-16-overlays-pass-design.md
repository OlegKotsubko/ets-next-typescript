# Overlays Pass — Design

**Status:** approved-in-brainstorm, pending spec review
**Date:** 2026-08-16

## Goal

Build **subsystem 3** — the global overlay (title) component system, its build-time registry, the `rundown_overlays` data + CRUD, and the rundown **editor** where an operator builds and configures a rundown of overlays. The live broadcast (`/preview`·`/air`, SSE bus, controller, per-display `rundown_overlay_data`) remains deferred to subsystem 4.

## Approach

Overlays are global React components under `overlays/<CATEGORY>/<TEMPLATE>/`, discovered by a build-time codegen into two generated registries (a lightweight **catalog** for admin/validation, and a **components** registry for rendering). Each overlay declares a Zod **widget schema** (operator-editable fields) that drives both the admin form and API validation. The editor lists overlays filtered by the tournament's discipline, configures each from its widget schema, and stores authored widget values inline on the `rundown_overlays` row. A protected dev page renders an overlay with sample data to verify GSAP/SCSS.

## Tech stack additions

- **`gsap`** (`^3.11`) — overlay enter/exit animations (new dependency; `sass` already present).
- Re-adds `titles:generate` codegen + the `predev`/`prebuild` hook (both removed in the foundation pass).

## Global constraints

- **Overlays are global**, organized by `category` (discipline dir) / `template` (widget dir); the registry key is the kebab **`model`** string on `settings.ts`.
- **Overlays use only SCSS modules + CSS variables** — no MUI, no inline hex, no Tailwind. Absolute positioning on a transparent 1920×1080 canvas. `font-display: block`.
- **`data.widget` is validated against the overlay's `model.ts` at the API boundary**, never re-validated in a render payload.
- **Integer ids / `project_id` FK isolation** preserved (`rundown_overlays` carries a denormalized `project_id`).
- **Generated registry files are committed** and regenerated by `titles:generate` (so Vitest/build don't need a codegen pre-step); a test asserts they're in sync.
- Green `typecheck`/`lint`/`build`/`vitest` at the end. **`db:migrate` is run by the operator**, not the agent.
- Deferred to broadcast (subsystem 4): SSE bus, `/preview`·`/air`, `displayUuid`, `rundown_overlay_data` (per-display runtime), the live controller, mixers/MIDI in anger.

## In scope

### 1. Overlay component contract
Each overlay is `overlays/<CATEGORY>/<TEMPLATE>/`:
- `index.tsx` — `export default function X({ data }: { data: XData })`; renders from `data.widget` (edited fields) + collected context (`data.match`/`data.participants`/`data.sponsors`); SCSS module only.
- `model.ts` — `export const model` (Zod object, validation) + optional `export const fields` (per-field UI meta: `label`, `canLiveUpdate`) + `export const actions` (declared thread-widget actions; universal air/preview/hide/update are implicit) + `export type Data`.
- `settings.ts` — `export default { model, category, template, widgetName, preview, color, isFullscreen }`.
- `animationIn.ts` / `animationOut.ts` — `export default (root: HTMLElement) => gsap.core.Timeline`.
- `<Template>.module.scss`.
Shared field/action contracts live in top-level `models/<Type>.ts` (e.g. `models/Timer.ts` → `TimerFields`, `TimerActions`), composed by an overlay's `model.ts`.

### 2. Widget-schema DSL + describeModel
`lib/overlays/widget-schema.ts`:
- Field builders `text/number/select/selectMulti/checkbox/listObject({ label?, required?, default?, choices?, canLiveUpdate? })`, each returning `{ zod, descriptor }`.
- `defineWidget(shape)` → `{ model: ZodObject, fields: FieldDescriptor[] }` (single source producing both validation schema and descriptors).
- `FieldDescriptor = { name, input_type, label, required, default?, choices?, can_live_update }`.
- `describeModel(entry)` returns the `FieldDescriptor[]` (default `label` = humanized field name; default `can_live_update` = **false** unless declared).

### 3. Build-time registry codegen
- `scripts/generate-overlay-registry.ts` scans `overlays/**` for folders containing `settings.ts`; emits two committed files:
  - `lib/overlays/catalog.generated.ts` — static imports of each overlay's `settings` + `model`/`fields`/`actions` (**no** `index.tsx`); powers admin + API validation.
  - `lib/overlays/components.generated.ts` — static imports of each overlay's `index.tsx` (`Component`) + `animationIn`/`animationOut`; powers rendering (dev harness now, broadcast later).
- `lib/overlays/registry.ts` builds `Map<model, entry>` and exposes: `listOverlays(discipline?)` (category === discipline OR `general`; honor an optional `allowedParticipantType`), `getOverlay(model)`, `getOverlayModel(model)`, `isDeclaredAction(model, action)`, `describeModel(model)`.
- `package.json`: `titles:generate` → the script; `predev`/`prebuild` run it.

### 4. Sample overlays (4)
Each with GSAP in/out + SCSS, proving a distinct path:
- `overlays/general/Text/` — a lower-third; single `text` field (`can_live_update`), `actions: ['next']`.
- `overlays/general/Scoreboard/` — two participants + scores from `data.match`/`data.participants`; proves collected-data rendering.
- `overlays/general/OpeningTimer/` — countdown; `TimerFields` + `actions: ['start','stop','reset']`; proves thread-widget actions + `can_live_update` on the duration.
- `overlays/general/Intro/` — a full-screen splash (`is_fullscreen: true`); proves the full-screen flag through the editor.
(All under `general` so they apply to every tournament this pass; discipline-specific dirs come with real content later.)

### 5. `rundown_overlays` table (+ migration)
Added to `db/schema.ts` per `database.md` §5, **plus the inline `data` column** (fork decision):
`{ id, rundownId→rundowns cascade, projectId→projects cascade (denormalized), model, category, template, widgetName, layer(1–7,default 1), color(1–7,default 1), displayFilter, previewImg, isFullscreen(default false), hasNextButton(default false), order(default 0), inMixer, outMixer, innerMixer, inTransitionCutPoint(double), outTransitionCutPoint(double), backgroundVideo, backgroundImage, data jsonb $type<{ widget: Record<string,unknown> }> default { widget: {} }, createdAt, updatedAt }`, index `(rundownId, order)`. One new `0001_*` migration.
> **Divergence from docs, accepted:** authored widget values live in `rundown_overlays.data.widget` this pass. The broadcast pass adds per-display `rundown_overlay_data` seeded from this authored default. Note it in `database.md`/`rundowns.md` at the end of the pass.

### 6. `rundown_overlays` CRUD
Under `/api/projects/[projectId]/rundowns/[id]/overlays` (`[id]` = rundownId; session-guarded; `projectId` from URL):
- `GET` — list a rundown's overlays ordered by `order`.
- `POST` — body `{ model, widgetName, layer?, color?, displayFilter?, isFullscreen? }`; server looks up `settings` by `model` from the catalog to fill `category`/`template`/`previewImg`/`isFullscreen` default, sets `data.widget` = `getOverlayModel(model).parse({})` (schema defaults), appends `order`. 400 if `model` unknown.
- `PATCH [overlayId]` — update `widgetName`/`layer`/`color`/`displayFilter`/`isFullscreen` and/or `data.widget` (validated against `getOverlayModel(model)`); filtered on `(id, projectId)`.
- `DELETE [overlayId]`.
- `POST reorder` — `{ orderedIds: number[] }` rewrites `order` (sequential writes; neon-http has no transactions).
- `store/apis/rundownOverlaysApi.ts` (RTK), tags scoped by rundown.

### 7. The editor UI
`app/(admin)/projects/[projectId]/rundowns/[rundownId]/page.tsx`:
- Loads the rundown, its overlays, and the tournament's `disciplineId` (→ tag name) for filtering.
- **Add overlay** — dialog listing `listOverlays(discipline)` from the catalog (name/preview/color/category); on pick, `POST` with a default `widgetName`.
- **Configure** — an `OverlayWidgetForm` rendering `describeModel(model)` FieldDescriptors (RHF + `zodResolver(getOverlayModel(model))`); plus `widgetName`/`layer`(1–7)/`color`(1–7)/`displayFilter`(''|1–10)/`isFullscreen`. Save → `PATCH`.
- **Reorder** — up/down buttons calling `reorder` (drag is a later polish; avoids a dnd dependency).
- **Delete**.
- Back-link to the rundowns list.

### 8. Dev render harness
`app/(admin)/dev/overlays/page.tsx` (protected): pick an overlay from the catalog, render its `components.generated` `Component` on a scaled transparent 1920×1080 stage with sample `data` (widget defaults + mock `match`/`participants`/`sponsors`), run `animationIn` on mount and an **Exit** button running `animationOut`. Proves render + GSAP + SCSS + theme CSS vars.

## Verification
1. `titles:generate` produces catalog + components registries importing all four sample overlays; a test asserts the committed files are in sync (re-run in a temp dir, compare).
2. Unit: `defineWidget`/`describeModel` (input_type/required/default/choices/can_live_update); `listOverlays` discipline filter; `getOverlayModel` validate; `isDeclaredAction`.
3. Route: `rundown_overlays` create validates `data.widget` against the model, derives category/template from the registry, `projectId` from URL; reorder rewrites order; PATCH rejects an invalid widget field.
4. Render: each sample overlay renders with sample data without throwing (jsdom).
5. Whole-project `typecheck`/`lint`/`build`/`vitest` green; migration generated (not run).

## Out of scope (later passes)
Broadcast bus + `/preview`·`/air` + `displayUuid` + `rundown_overlay_data` + live controller (subsystem 4/5); MIDI, Bluetooth, timer WebSocket, ATEM/seating, real per-discipline overlay content at scale.
