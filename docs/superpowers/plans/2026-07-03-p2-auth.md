# P2 — Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Email + password login via better-auth with sessions in Neon Postgres — `/login` page, middleware gating `/admin/*` and `/api/projects/*`, a server-readable session, and a `create-user.ts` bootstrap script — so P5 (admin workspace) has an authenticated operator.

**Architecture:** better-auth (single package, v1.6) with the built-in Drizzle adapter over the existing `@/db` Neon HTTP instance. Auth tables (`users`, `sessions`, `accounts`, `verifications`) are hand-written into `db/schema.ts` (plural names, `usePlural: true` on the adapter) and migrated with the normal `db:generate`/`db:migrate` cycle; `rundowns.owner_id` gets its deferred FK. Public sign-up is **disabled** (`disableSignUp: true`) — the create-user script builds its own sign-up-enabled better-auth instance from a shared `buildAuthOptions()` factory. Middleware does an optimistic cookie-presence check (`getSessionCookie`); real session validation is server-side `auth.api.getSession` in pages/route handlers.

**Tech Stack:** better-auth `^1.6.23` · drizzle-orm `^0.45.2` + drizzle-kit `^0.31.10` (upgraded — better-auth peer requirement) · react-hook-form `^7.53.0` + `@hookform/resolvers` `^3.9.0` (zodResolver) · MUI 6 (login/admin UI) · tsx (dev, runs the script).

## Global Constraints

- **Reality check vs `docs/auth.md` (written against an older better-auth):** there is **no `better-auth-next` package on npm**. All imports come from `better-auth` itself: `better-auth/next-js` (route handler), `better-auth/react` (client), `better-auth/cookies` (`getSessionCookie`), `better-auth/adapters/drizzle` (adapter). Task 9 syncs the docs.
- **Dependency floor conflict, resolved in Task 1:** better-auth `1.6.x` declares peer deps `drizzle-orm@^0.45.2` and `drizzle-kit@>=0.31.4`; the repo has `^0.36.4`/`^0.27.2`. Both drizzle-kit 0.27 and 0.31 emit snapshot format `"7"`, so the upgrade does not invalidate `db/migrations/meta/`. Tech-stack policy: versions are minimums, "bump deliberately" — this is that deliberate bump.
- **No public sign-up is a server-side property, not a UI omission.** `emailAndPassword.disableSignUp: true` on the app's `auth` instance closes `/api/auth/sign-up/email`. Only `scripts/create-user.ts` (via `buildAuthOptions({ allowSignUp: true })`) can create users.
- **`/preview/*` and `/air/*` stay public** (OBS browser sources); middleware matcher covers only `/admin/:path*` and `/api/projects/:path*`. `/login` is the only public admin page.
- **Middleware cookie check is optimistic** (cookie presence, not validity). Every protected page/route handler must additionally call `auth.api.getSession` and 401/redirect. P2's `/admin` placeholder demonstrates the pattern.
- **House style (P0 ESLint):** no semicolons, 2-space indent, single quotes. `db/`, `test/`, `scripts/` aren't covered by `next lint` — follow house style anyway.
- **Vitest 4, global jsdom**; node-only tests opt out with a `// @vitest-environment node` docblock. Guarded DB tests follow the P1 pattern: `config({ path: ['.env.local', '.env'] })` + `describe.skipIf(!hasDb)` + dynamic `await import(...)` inside the test.
- **`db:migrate` never runs inside `next build`** (`docs/database.md`, `CLAUDE.md`). Migrations are applied explicitly against the right `DATABASE_URL`.
- **Env contract** (`.env.example` already lists all three): `DATABASE_URL`, `BETTER_AUTH_SECRET` (32-byte hex, `openssl rand -hex 32`), `BETTER_AUTH_URL` (must match the browser origin, `http://localhost:3000` in dev).
- Every task ends in a commit. Work on a branch off `main` (e.g. `p2-auth`), not on `main` directly.

export const users = pgTable('users', {
  id: text('id').primaryKey(),                  // better-auth generates text ids
  name: text('name').notNull(),
  email: text('email').notNull().unique(),
  emailVerified: boolean('email_verified').default(false).notNull(),
  image: text('image'),
  createdAt: timestamp('created_at').defaultNow().notNull(),
  updatedAt: timestamp('updated_at').defaultNow().$onUpdate(() => new Date()).notNull(),
})

  id: text('id').primaryKey(),
  expiresAt: timestamp('expires_at').notNull(),
  token: text('token').notNull().unique(),
  createdAt: timestamp('created_at').defaultNow().notNull(),
  updatedAt: timestamp('updated_at').defaultNow().$onUpdate(() => new Date()).notNull(),
  ipAddress: text('ip_address'),
  userAgent: text('user_agent'),
  userId: text('user_id')
    .notNull()

}, (t) => [index('sessions_user_idx').on(t.userId)])

export const accounts = pgTable('accounts', {
  id: text('id').primaryKey(),
  accountId: text('account_id').notNull(),
  providerId: text('provider_id').notNull(),    // 'credential' for email+password
  userId: text('user_id')
    .notNull()
    .references(() => users.id, { onDelete: 'cascade' }),

  refreshToken: text('refresh_token'),
  idToken: text('id_token'),
  accessTokenExpiresAt: timestamp('access_token_expires_at'),
  refreshTokenExpiresAt: timestamp('refresh_token_expires_at'),
  scope: text('scope'),
  password: text('password'),                   // scrypt hash for email+password
  createdAt: timestamp('created_at').defaultNow().notNull(),
  updatedAt: timestamp('updated_at').defaultNow().$onUpdate(() => new Date()).notNull(),
}, (t) => [index('accounts_user_idx').on(t.userId)])

import { betterAuth } from 'better-auth'
import { drizzleAdapter } from 'better-auth/adapters/drizzle'
import { db } from '@/db'
import * as schema from '@/db/schema'

// disableSignUp keeps POST /api/auth/sign-up/email closed in every deploy —
// "no public sign-up" is a server property, not a missing UI. Only
// scripts/create-user.ts opts out via its own instance.
export function buildAuthOptions({ allowSignUp = false }: { allowSignUp?: boolean } = {}) {
  return {
    database: drizzleAdapter(db, { provider: 'pg', schema, usePlural: true }),
    emailAndPassword: {
      enabled: true,
      disableSignUp: !allowSignUp,
      autoSignIn: true,
    },
    secret: process.env.BETTER_AUTH_SECRET!,
    baseURL: process.env.BETTER_AUTH_URL!,
  }
}

export const auth = betterAuth(buildAuthOptions())

```ts
// lib/auth-guard.ts
const PROTECTED_PREFIXES = ['/admin', '/api/projects']

export type GuardDecision = 'allow' | 'redirect-login' | 'unauthorized'

// Optimistic check: middleware only sees whether the session cookie EXISTS.
// Real validation is auth.api.getSession server-side in every protected
// page / route handler (see docs/auth.md).
export function guardRequest(pathname: string, hasSessionCookie: boolean): GuardDecision {
  const isProtected = PROTECTED_PREFIXES.some(
    (p) => pathname === p || pathname.startsWith(`${p}/`),
  )
  if (!isProtected || hasSessionCookie) return 'allow'
  return pathname.startsWith('/api/') ? 'unauthorized' : 'redirect-login'
}
```

```ts
// middleware.ts
import { NextResponse, type NextRequest } from 'next/server'
import { getSessionCookie } from 'better-auth/cookies'
import { guardRequest } from '@/lib/auth-guard'

export function middleware(req: NextRequest) {
  const decision = guardRequest(req.nextUrl.pathname, Boolean(getSessionCookie(req)))
  if (decision === 'unauthorized') {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
  }
  if (decision === 'redirect-login') {
    const url = req.nextUrl.clone()
    url.pathname = '/login'
    return NextResponse.redirect(url)
  }
  return NextResponse.next()
}

export const config = {
  matcher: ['/admin/:path*', '/api/projects/:path*'],
}
```

```ts
// test/auth/roundtrip.test.ts
// @vitest-environment node
import { describe, it, expect } from 'vitest'
import { config } from 'dotenv'

config({ path: ['.env.local', '.env'] })
process.env.BETTER_AUTH_URL ||= 'http://localhost:3000'
const hasEnv = Boolean(process.env.DATABASE_URL && process.env.BETTER_AUTH_SECRET)

// Requires a migrated Neon branch (0002 applied). Skipped when env is unset.
describe.skipIf(!hasEnv)('auth round-trip', () => {
  it('blocks public sign-up, creates via script path, signs in, reads the session', async () => {
    const { betterAuth } = await import('better-auth')
    const { auth, buildAuthOptions } = await import('@/lib/auth')
    const { db } = await import('@/db')
    const { users } = await import('@/db/schema')
    const { eq } = await import('drizzle-orm')

    const email = `e2e-${Date.now()}@example.com`
    const password = 'roundtrip-password-1'

    try {
      // 1. The app instance refuses sign-up (disableSignUp).
      await expect(
        auth.api.signUpEmail({ body: { email, password, name: email } }),
      ).rejects.toThrow()

      // 2. The script-side instance can create the user.
      const scriptAuth = betterAuth(buildAuthOptions({ allowSignUp: true }))
      await scriptAuth.api.signUpEmail({ body: { email, password, name: email } })

      // 3. Sign in on the app instance -> session cookie in the response.
      const res = await auth.api.signInEmail({
        body: { email, password },
        asResponse: true,
      })
      const setCookie = res.headers.get('set-cookie') ?? ''
      expect(setCookie).toContain('better-auth.session_token')

      // 4. The cookie resolves back to the user server-side.
      const cookie = setCookie.split(';')[0]
      const session = await auth.api.getSession({ headers: new Headers({ cookie }) })
      expect(session?.user.email).toBe(email)
    } finally {
      // Cascades to sessions + accounts.
      await db.delete(users).where(eq(users.email, email))
    }
  })
})
```
