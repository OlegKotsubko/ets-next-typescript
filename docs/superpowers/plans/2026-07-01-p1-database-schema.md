# P1 — Database & Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a migratable, seeded Postgres schema via Drizzle + the Neon HTTP driver — `projects`, `rundowns`, `rundown_items` — with a singleton seed project, so P2 (auth) and P4/P5 (broadcast + admin) have a database to build on.

**Architecture:** One `db/schema.ts` holds the Drizzle table definitions and the `createProjectSchema` Zod contract. `db/index.ts` exports a single `db` instance backed by `@neondatabase/serverless` (HTTP driver — no pooled connections). Migrations are generated by `drizzle-kit` and committed as SQL; a hand-written custom migration seeds one project at a fixed UUID (`SEED_PROJECT_ID`) so the rest of the app has a project to scope to before the Add-Project UI exists. Schema-shape tests run with no database; the insert/select round-trip is guarded to run only when `DATABASE_URL` is set.

**Tech Stack:** Drizzle ORM `^0.36` + drizzle-kit `^0.27` · `@neondatabase/serverless` `^0.10` · Zod `^3.23` · `dotenv` (dev, loads `.env.local` for CLI + guarded tests). Versions per `docs/tech-stack.md`.

## Global Constraints

- Builds on P0 (merged to `main`): Next.js 15, TS path alias `@/*` → repo root, Vitest 4 with a **global jsdom** environment and `@vitejs/plugin-react`. Import app code as `@/db`, `@/db/schema`.
- **Package version floors** (pin with `^` from `docs/tech-stack.md`): `drizzle-orm@^0.36.0`, `drizzle-kit@^0.27.0`, `@neondatabase/serverless@^0.10.0`, `zod@^3.23.0`. `dotenv` is a P1-introduced dev dependency (not in the tech-stack table) used only to load `.env.local` for the drizzle CLI and the guarded round-trip test.
- **House style (P0 ESLint):** no semicolons, 2-space indent. `db/`, `test/`, and `scripts/` are **not** covered by `next lint` (it only lints `app`/`lib`/`components`/`pages`/`src`) — write them in house style anyway for consistency; a future flat-config migration will lint them.
- **Multi-tenancy is load-bearing** (`docs/database.md`): every entity table has `project_id uuid not null references projects(id) on delete cascade`, every supporting index starts with `project_id`/`rundown_id`, and the server derives `projectId` from the URL — never the body. P1 lays the schema that enforces this.
- **Scope boundary — auth tables are NOT created here.** base-app-scope lists `users` under P1 but says "better-auth tables come in P2 — coordinate the adapter." better-auth owns its auth tables and uses **text** user IDs. So P1 creates only `projects`/`rundowns`/`rundown_items`; `rundowns.owner_id` is a **nullable `text`** column with **no FK** yet. P2 adds the `users` table (and may add the FK constraint via migration).
- **Deferred by design, do not add here:** `rundown_items.layer` (owned by `2026-06-21-multi-layer-preview-air-design.md` as its own migration) and the 3 MIDI collaboration tables (stay in the MIDI feature plan). Adding a column later is a normal `db:generate` → `db:migrate` cycle.
- **`db:migrate` never runs inside `next build`** (`docs/database.md`, `CLAUDE.md`).
- Every task ends in a commit. Work on a branch off `main` (not on `main` directly).

```ts
// db/schema.ts
import { pgEnum, pgTable, uuid, text, date, timestamp } from 'drizzle-orm/pg-core'
import { z } from 'zod'

export const projectMode = pgEnum('project_mode', ['team_vs_team', 'player_vs_player'])

export const projects = pgTable('projects', {
  id: uuid('id').defaultRandom().primaryKey(),
  name: text('name').notNull(),                 // project_name
  mode: projectMode('mode').notNull(),          // project_mode
  label: text('label').notNull(),               // project_label — overlay-package folder under projects/
  pictureUrl: text('picture_url'),              // project_picture
  eventDate: date('event_date'),                // project_date
  createdAt: timestamp('created_at').defaultNow().notNull(),
  updatedAt: timestamp('updated_at').defaultNow().notNull(),
})

// Operator-supplied fields only. The server never trusts an id/projectId from the body.
export const createProjectSchema = z.object({
  name: z.string().min(1).max(120),
  mode: z.enum(['team_vs_team', 'player_vs_player']),
  label: z.string().min(1),                     // validated against the live projects/ scan at the API layer (P6)
  pictureUrl: z.string().url().optional(),
  eventDate: z.string().date().optional(),      // yyyy-mm-dd
})
```

```ts
// db/index.ts
import { neon } from '@neondatabase/serverless'
import { drizzle } from 'drizzle-orm/neon-http'
import * as schema from './schema'

// The HTTP driver opens a fresh connection per query — safe in serverless.
const sql = neon(process.env.DATABASE_URL!)
export const db = drizzle(sql, { schema })
```

```ts
// db/constants.ts
// Fixed id for the singleton seed project. MVP has no Add-Project UI yet (that's P6),
// so P4/P5 scope everything to this one project. Shared by the seed migration and app
// code so the value never drifts.
export const SEED_PROJECT_ID = '00000000-0000-0000-0000-000000000001'
```

```ts

// drizzle-kit does not auto-load .env.local; load it explicitly.

  schema: './db/schema.ts',
  out: './db/migrations',
  dialect: 'postgresql',

export const rundowns = pgTable('rundowns', {
  id: uuid('id').defaultRandom().primaryKey(),
  projectId: uuid('project_id')
    .notNull()
    .references(() => projects.id, { onDelete: 'cascade' }),
  name: text('name').notNull(),
  // better-auth user id (text). No FK until the users table exists in P2.
  ownerId: text('owner_id'),
  createdAt: timestamp('created_at').defaultNow().notNull(),
  updatedAt: timestamp('updated_at').defaultNow().notNull(),
}, (t) => ({
  byProject: index('rundowns_project_idx').on(t.projectId),
}))

export const rundownItems = pgTable('rundown_items', {
  id: uuid('id').defaultRandom().primaryKey(),
  rundownId: uuid('rundown_id')
    .notNull()
    .references(() => rundowns.id, { onDelete: 'cascade' }),
  projectId: uuid('project_id')                 // denormalized for direct project-scoped filtering
    .notNull()
    .references(() => projects.id, { onDelete: 'cascade' }),
  titleKey: text('title_key').notNull(),        // folder under projects/<label>/titles/
  label: text('label'),                         // operator-facing display label (Add Template modal)
  position: integer('position').notNull(),
  data: jsonb('data').$type<Record<string, unknown>>().notNull(),  // validated against the title's model.ts
}, (t) => ({
  byRundown: index('rundown_items_rundown_idx').on(t.rundownId, t.position),
}))
```

```ts
// @vitest-environment node
// test/db/roundtrip.test.ts
import { describe, it, expect } from 'vitest'
import { config } from 'dotenv'

config({ path: '.env.local' })
const hasDb = Boolean(process.env.DATABASE_URL)

// Requires a migrated + seeded Neon branch. Skipped when DATABASE_URL is unset.
describe.skipIf(!hasDb)('db round-trip', () => {
  it('inserts and reads back a rundown under the seed project', async () => {
    const { db } = await import('@/db')
    const { rundowns } = await import('@/db/schema')
    const { SEED_PROJECT_ID } = await import('@/db/constants')
    const { eq } = await import('drizzle-orm')

    const [row] = await db
      .insert(rundowns)
      .values({ projectId: SEED_PROJECT_ID, name: 'Round-trip test' })
      .returning()
    expect(row.id).toBeDefined()

    const found = await db.select().from(rundowns).where(eq(rundowns.id, row.id))
    expect(found[0]?.name).toBe('Round-trip test')

    await db.delete(rundowns).where(eq(rundowns.id, row.id))
  })
})
```
