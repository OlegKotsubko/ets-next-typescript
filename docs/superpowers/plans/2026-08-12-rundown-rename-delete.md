# Rundown Rename/Delete Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire up rename and delete for a rundown — API route handlers, RTK Query hooks, and UI on both the rundowns list page and the rundown stub/detail page.

**Architecture:** The `rundowns` table, Zod schemas, and generic `createCrudHandlers` CRUD factory already exist and already support `PATCH`/`DELETE` — this plan only exports the already-built handlers/hooks and adds the MUI dialogs that call them, following the exact patterns already used by the existing "Add Rundown" dialog in `app/admin/[projectId]/rundowns/page.tsx`.

**Tech Stack:** Next.js 16 App Router, TypeScript, MUI 6 (`@mui/material`, `@mui/icons-material`), Redux Toolkit Query, Zod, Vitest.

## Global Constraints

- Every project entity API route derives `projectId` from the URL, never the request body — already true of `createCrudHandlers`; do not change this.
- No new automated tests: `createCrudHandlers`'s `PATCH`/`DELETE` behavior is already fully covered generically in `test/lib/crud/createCrudHandlers.test.ts`, and no other entity (`teams`, `players`) duplicates that coverage per-route. No component tests exist for any admin page in this repo (`/admin`, `/login`, the Data hub, the rundowns pages) — don't introduce the first one here.
- UI dialogs must reuse the existing error-handling convention: `.unwrap()` inside try/catch, `getErrorMessage(err, fallback)` from `@/lib/errors/getErrorMessage` rendered in an MUI `Alert`, submit button `disabled={... || isLoading}`.
- Delete confirmation is a simple Cancel/Delete dialog — no type-to-confirm.
- Full design spec: `docs/superpowers/specs/2026-08-12-rundown-rename-delete-design.md`.

```ts
import { and, eq } from 'drizzle-orm'
import { db } from '@/db'
import { rundowns } from '@/db/schema'
import { auth } from '@/lib/auth'
import { createRundownSchema, updateRundownSchema } from '@/db/schemas/rundowns'
import { createCrudHandlers } from '@/lib/crud/createCrudHandlers'

export async function GET(req: Request, { params }: { params: Promise<{ projectId: string; id: string }> }) {
  const session = await auth.api.getSession({ headers: req.headers })
  if (!session) return new Response('Unauthorized', { status: 401 })

  const { projectId, id } = await params
  const [row] = await db.select().from(rundowns).where(and(eq(rundowns.id, id), eq(rundowns.projectId, projectId)))
  if (!row) return new Response('Not found', { status: 404 })
  return Response.json(row)
}

export const { PATCH, DELETE } = createCrudHandlers({ table: rundowns, createSchema: createRundownSchema, updateSchema: updateRundownSchema })
```

Only the imports and the trailing `export const { PATCH, DELETE } = ...` line are new; `GET` is untouched.

- [ ] **Step 3: Add the menu-open, rename, and delete handlers**

After the existing `closeDialog`/`handleCreate` functions (before the `return (`), add:

```ts
  function openMenu(e: React.MouseEvent<HTMLElement>, rundown: Rundown) {
    e.preventDefault()
    e.stopPropagation()
    setMenuAnchor(e.currentTarget)
    setMenuTarget(rundown)
  }

  function closeMenu() {
    setMenuAnchor(null)
    setMenuTarget(null)
  }

  function openRenameDialog() {
    if (!menuTarget) return
    setRenameId(menuTarget.id)
    setRenameName(menuTarget.name)
    setRenameError(null)
    setRenameOpen(true)
    closeMenu()
  }

  function closeRenameDialog() {
    setRenameOpen(false)
    setRenameError(null)
  }

  async function handleRename() {
    if (!renameId) return
    setRenameError(null)
    try {
      await updateRundown({ projectId, id: renameId, data: { name: renameName } }).unwrap()
      setRenameOpen(false)
    } catch (err) {
      setRenameError(getErrorMessage(err, 'Failed to rename rundown. Please try again.'))
    }
  }

  function openDeleteDialog() {
    if (!menuTarget) return
    setDeleteTarget(menuTarget)
    setDeleteError(null)
    setDeleteOpen(true)
    closeMenu()
  }

  function closeDeleteDialog() {
    setDeleteOpen(false)
    setDeleteError(null)
  }

  async function handleDelete() {
    if (!deleteTarget) return
    setDeleteError(null)
    try {
      await deleteRundown({ projectId, id: deleteTarget.id }).unwrap()
      setDeleteOpen(false)
    } catch (err) {
      setDeleteError(getErrorMessage(err, 'Failed to delete rundown. Please try again.'))
    }
  }
```
